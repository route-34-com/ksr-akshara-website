# KSR Akshara Academy: redesign concept

A pitch prototype for a new ksrakshara.org (CBSE school, Tiruchengode). Static HTML generated by Python, no framework, no npm.

## Commands

```bash
python3 build.py                                   # regenerate every page (run after any change to build.py or data)
python3 -m http.server 8765                        # preview at http://localhost:8765/
python3 news_feed.py                               # refresh news from the school's YouTube channel -> assets/data/news.json
/tmp/ksrvenv/bin/python optimize_images.py         # after adding photos: WebP copies sized for display (Pillow)
/tmp/ksrvenv/bin/python vendor_assets.py           # after using a new Phosphor icon: re-trim the icon font (fonttools, brotli)
/tmp/ksrvenv/bin/python tree_geometry.py --bake    # after changing a leaf outline: re-round corners (shapely)
```

`/tmp/ksrvenv` is a scratch venv (Pillow, shapely, fonttools, brotli); recreate it if missing. `build.py` itself needs only the standard library.

## Layout

- `build.py`: every page's HTML lives here as Python f-strings; `PAGES` lists slug, title, description, function. Output is `<slug>/index.html`. Never hand-edit generated `index.html` files.
- `assets/css/site.css` is hand-written. `assets/css/vendor.css` is generated (fonts + trimmed icons).
- `assets/js/site.js`: all interactivity, no dependencies.
- `tree_geometry.py`: the emblem tree. Leaf outlines come from `assets/data/akshara-tree.json` (traced from the logo), polished into `akshara-tree-clean.json` by `--bake`. `DRAWN` hand-draws leaves whose trace was bad (`inner1`); `trunk()` and `FIGURE` are drawn by hand.

## Rules that are easy to break

- **Keep every URL slug identical to the live WordPress site** (`/about-us/`, `/events/`, ...). That is an SEO promise in the pitch.
- **Content must be real.** Facts, names, numbers and news come from ksrakshara.org or the school's YouTube channel. Never invent events, dates, results or testimonials.
- **Copy style:** no em or en dashes anywhere in visible text; use a hyphen, comma or full stop.
- Photos go through `webp()` in the build; `og:image` deliberately stays JPEG.

## The tree (`/akshara-tree/`, homepage hero)

- Hover and selection use `<use>` copies in `.lift-layer` (trunk: `.lift-under`, beneath the crown). **Never re-order or move leaf DOM nodes**: that restarts animations and made leaves vanish in Safari.
- Wind is written as SVG `transform` attributes each frame from JS. Keep the `.wind` wrapper *outside* `#lv-<key>`: if the element a `<use>` mirrors changes every frame, Safari rebuilds the copy every frame (this dropped the page to 13 fps).
- No blur filters or `backdrop-filter` on or over the animated tree; use static gradients. Check with a WebKit fps test after changes (target 60).
- The selected leaf is a white-to-sky gradient (`#g-sel`) with a deep-blue icon, not red.
- `data-tree="full"` is the tree page; `data-tree="mini"` is the homepage, where a leaf links to `/akshara-tree/#<key>`.

## Verifying

- Test in WebKit (Playwright), not only Chrome: this site has had Safari-only bugs.
- Check phones at 390px wide for horizontal overflow.
- Lighthouse (mobile) was 96-98 performance and 100 accessibility / best practices / SEO; don't regress it (no external CSS or font CDNs).
